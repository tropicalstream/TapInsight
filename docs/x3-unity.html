Fable Unity Guide · the official RayNeo path

Building AR Apps for the X3 Pro
with Unity, from scratch

The official OpenXR ARDK route — and the only one that unlocks real spatial AR: gaze interaction, 6DoF, plane & image tracking. A self-contained, bottom-up build for graphics, sound, and the glasses' UI/UX, manifest included.

00Two honest truths first

Why Unity: it's RayNeo's officially supported path, and the only way to get true spatial AR on the X3 (the device has no ARCore). The XR Plugin renders both eyes and head tracking for you — no hand-rolled binocular compositor. Pick Unity for 3D anchored content; pick native Android for 2D HUDs/media/voice.

⚠️ Truth 1 — Unity is heavier on the AR1 Gen1. It works (the official sample ships) but the chip is strained; treat 30 fps as the ceiling and budget aggressively or you hit the thermal-reboot path faster than native.

⚠️ Truth 2 — an AI can't click the Unity Editor. A frontier model writes every C# script, the manifest, and Project Settings, and gives exact Editor steps — but a human performs the GUI wiring. Start from the official sample to minimize blind clicks.

01–02Setup, version-pinned

Vendor-pinned: Unity 2022.3.36f1 + Android Build Support, OpenJDK, SDK & NDK. Import the OpenXR Unity ARDK (1.1.2). Fastest start — clone the official sample and edit from a known-good baseline: github.com/MaxManausa/RayNeoX3Pro-MITSample. Get ADB working (Settings → General → swipe far-left, bounce the wall 10×).

03–04Scaffold & manifest

New 3D (URP) project → delete the default Camera + Light → drag the XR Plugin prefab from Packages/RayNeo OpenXR ARDK/.../Prefab into the scene. Its children: Head (3DoF camera, renders both eyes), LaserBeam (gaze ray), BeamGraphic (visible ray), LaserBeamDot (cursor). Set Game view to 640×480.

Provide a custom manifest at Assets/Plugins/Android/AndroidManifest.xml so Unity merges it. The three non-negotiables (every X3 app):

<meta-data android:name="com.rayneo.mercury.app" android:value="true" />
<category android:name="com.rayneo.intent.category.AR_APP" />
<!-- and NEVER declare ar_mode (forces left-lens-only) -->

06Graphics — for a waveguide

The one setting that defines AR look: on the Head camera, Clear Flags = Solid Color, color = pure black (0,0,0). Black isn't drawn — it's the real world showing through. No skybox, no lit background, or you paint a wall of light over reality. This is the #1 beginner mistake.

URP, mobile-tuned (no HDR, MSAA ≤2×, shadows off). Unlit / emissive materials for the hologram glow — cheap and gorgeous on a transparent display. Particles: additive, capped at a few hundred, no lights/collision. TextMeshPro on a world-space Canvas. Budget: low-thousands of triangles, under ~50 draw calls, 30 fps locked.

07Sound

Native Unity AudioSource — no Web Speech limitation here. For spatial audio set Spatial Blend = 1 (3D) so sound comes from the object's position. Request audio focus and release it on pause via the ARDK: AudioFocus.SetAudioFocusStatus(true/false) + register/unregister the change callback. Mic capture uses audio_source_record=voice_recognition (wearer-only, 16 kHz) — and you must set =off on stop or the mic stays seized.

08–09UI/UX & AR capabilities

Gaze is the cursor: the LaserBeam projects from view-center, the dot marks the hit — put a Collider on anything selectable. TouchPad (ARDK-abstracted): slide = move focus, single tap = select what the gaze dot is on, double tap = back/exit (wire it everywhere — users expect it), triple = special. Slide direction can flip with "natural mode" — design forward/back, not left/right. UI lives on a world-space Canvas ~1.5–2 m ahead, inside the ~36° FOV.

Unity-only AR (the native path can't): 3DoF (always on), Gaze Ray, 6DoF (SLAM/ShareCamera — power-hungry, drifts, no ARCore), image tracking, plane detection (3–5 s, at init only), face, gestures. Use 3DoF + Gaze for most apps; reach for the rest only when world-anchoring is essential, and budget the thermal cost.

10Worked example — the interactive orb

A glowing orb floats ~2 m ahead; gaze + single-tap pulses its light, fires a particle burst, plays a spatial chime; a world-space panel counts taps; double-tap exits. The full Editor steps + the Orb.cs / AppController.cs scripts are in the MD guide.

void OnSingleTap() {
  if (Physics.Raycast(head.position, head.forward, out var hit, 5f)
      && hit.collider.CompareTag("Selectable"))
    hit.collider.GetComponent<Orb>()?.Activate();   // pulse + spatial sound
}
void OnDoubleTap() => Application.Quit();             // expected exit gesture

12–13Performance & the failure modes

Application.targetFrameRate = 30; strip Quality Settings; cap draw calls/particles; disable SLAM/planes when unused (vendor budget: ~30 fps, APL <13%, <500 mA). The big issues: grey/opaque background (camera clear not black — occludes the world), one-eye render (ar_mode present or no XR Plugin), can't select (no Collider), double-tap doesn't exit (not wired), mic stays on (no =off), plane detection never fires (init-only, 3–5 s), 6DoF drift / heat (SLAM, no ARCore), and thermal reboot from over-rendering — Unity reaches it faster than native, so lock 30 and stay lean.
