How to bring Apple Watch vitals, HealthKit metrics, iCloud sync, and Apple's new multimodal on-device AI to a pair of Android AR glasses — built on the developer frameworks Apple shipped at WWDC 2026.

00The fact that governs everything

The RayNeo X3 Pro runs Android 14. HealthKit, CloudKit, Foundation Models, App Intents, VisionKit are Apple-platform-only — none can run on the glasses. So "Apple Health on the X3" means a three-tier bridge: the Watch senses, an iPhone companion app reads + reasons + relays, the glasses display and act. It's exactly how RayNeo already bridges GPS from the phone — you're extending a proven pattern.

One exception: WeatherKit REST, Apple Maps Server API, MusicKit web, and APNs expose token-auth REST endpoints the Android glasses can call directly — no iPhone (§6).

01What WWDC 2026 changed

Foundation Models — now hybrid, provider-agnostic, multimodal

The on-device Apple model is reached through a Language Model protocol that also accepts Claude, Gemini, or any conforming provider behind the same Swift API. Prompts are now multimodal — images alongside text — with on-device Vision tools (OCR, barcode) the model can call. Private Cloud Compute is free for Small-Business-Program apps under 2M downloads.

Why it matters for AR: the iPhone bridge can take a camera frame from the glasses, pair it with live Watch vitals, and run one multimodal reasoning step on-device — "what am I looking at, and is anything notable given my heart rate?" That's the flagship use case in §5.

HealthKit: WWDC26 opened heart-rate & cycling-power zones to third-party apps — read the config, get live zone updates during a workout, set custom boundaries. iOS 27 adds perimenopause/menopause tracking. App Intents: new View Annotations API for on-screen awareness. Plus Image Playground & Visual Intelligence APIs.

04The relay — one JSON envelope, three transports

{ "type":"health", "ts":1718200000, "hr":78, "spo2":98,
  "hrZone":2, "kcalActive":142,
  "rings":{"move":0.62,"exercise":0.40,"stand":0.75} }

(a) BLE / LAN — lowest latency; extend the glasses' companion server (/api/health) or a BLE GATT characteristic. (b) CloudKit — the system-of-record; private database + CKQuerySubscription silent push, syncs across the user's own devices. (c) Cloudflare-tunnelled relay — the exact TapInsight image_relay.py pull pattern, IP-proof, works on any network. Recommended: (c) for record + away-from-home, (a) for the live tick.

05The Apple Intelligence layer — the point

The iPhone isn't a pipe, it's a reasoning node between the Watch's senses and the glasses' eyes. One multimodal call fuses both:

import FoundationModels
let session = LanguageModelSession(model: .systemDefault)  // or Claude / Gemini
let reply = try await session.respond(to: Prompt {
    "Heart rate \(hr) bpm, SpO₂ \(spo2)%. The glasses camera sees:"
    cameraFrame                       // multimodal image input — new in WWDC26
    "What is this, and anything notable given the vitals?"
})
relayToGlasses(text: reply.content)   // HUD + readout-engine TTS

On-device keeps vitals private. The provider protocol lets you A/B Apple's model against Claude or Gemini with no rewrite. Threshold events (an SpO₂ dip, a zone change) compose a short on-device summary and ring the glasses' existing notification bell.

07–08Glasses side, and the honest limits

The glasses half is light — all patterns from the starter guide: receive the envelope (CompanionServer / relay pull / BLE), render a metrics tier on the binocular HUD (white-on-black, throttled redraws — remember the dim-mode reboot lesson), feed notable changes to the readout engine, and hand health context + camera frames to the assistant.

Limits, honestly: health data is sensitive — keep it on-device, and any relay must be the user's own and opt-in (App Review enforces this). No medical claims — consumer SpO₂/HR are wellness signals, not diagnostics. The dense live stream needs an Apple Watch + a Watch extension; phone-only samples are sparse. And APIs move fast — a frontier model should fetch the live Apple docs and WWDC26 session videos before building, treating every signature here as a shape to confirm, not a contract.
